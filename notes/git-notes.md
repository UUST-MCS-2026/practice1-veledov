# Заметки по Git

## Эксперимент А: пустая папка
Git не увидел пустую sandbox, потому что он хранит содержимое файлов, а в пустой папке хранить нечего. Папки в Git существуют только как часть пути к файлу, в объектах-деревьях.
Git хранит файлы (blob-объекты), а не папки.
Я добавил файл sandbox/.gitkeep, и теперь в папке есть файл, поэтому она попала в репозиторий.

## Эксперимент Б: исчезнувший файл
Файл secret.txt из проекта пропал, но из репозитория не исчез: он остался в истории, в старом коммите.
Команда: git show 3361622:secret.txt
Результат: мой пароль: 12345
Вывод для случайно закоммиченного пароля: удаление файла новым коммитом его из истории не убирает, пароль можно достать. Такой пароль считается скомпрометированным и его нужно заменить.

## Эксперимент В: .gitignore
Одного .gitignore не хватило, потому что он действует только на файлы, которые Git ещё не отслеживает. output.log и __pycache__ уже попали в коммит, поэтому Git продолжал следить за ними.
Дополнительно понадобилась команда: git rm --cached (для output.log и git rm -r --cached для __pycache__). Она убирает файл из отслеживания, но оставляет его на диске. В истории он при этом остаётся.

## Шаг 6: цепочка хешей
HEAD -> ref: refs/heads/main
refs/heads/main -> c1e149957e59af6730f79f22560664421ace9193 (commit "убрал мусор из отслеживания")
commit -> tree 3eb0525b9f78f50f7bee7023031452a6a659420e
tree -> blob 27369479aea4fa55082cbf0f7cf70b290dc754cd (README.md)
blob -> текст "# practice1-veledov / Практика 1: Git и GitHub. Здесь лежат мои заметки и эксперименты."
У коммита также есть parent 51f6c5181b6c9bb7528e42f12bf8e080aabca367, то есть коммиты ссылаются друг на друга.

## Вопросы
1. Объектов в .git/objects было 33, стало 36 (+3). a.txt и b.txt указывают на один и тот же blob 5ed8fdc8fe57ea68550f80cf5b1b518a8b303477, потому что хеш объекта считается из содержимого файла, а содержимое одинаковое. Имена файлов хранятся не в blob, а в дереве. Новых объектов три: этот общий blob, новое дерево и коммит.
2. git hash-object c.txt до git add дал 3390fbaa6a0a3304b7b0a7f0af6eb99e45b18ef1. После коммита git ls-files -s показал тот же хеш. Он совпал, потому что хеш вычисляется только из содержимого файла и не зависит от того, добавлен ли файл в репозиторий.
3. После правки одного символа хеш c.txt изменился с 3390fbaa6a0a3304b7b0a7f0af6eb99e45b18ef1 на 07d45ebecebf2c76fd59bbe8b921ce39a0adfdc3. Хеш корневого дерева изменился с a21a71600c67af3f2ab73d62f1a31e6d473bb495 на d6eaa83e9154f4ee32a47395358cad522dd367ce. Хеши README.md (27369479...), .gitignore (9291ddf5...), a.txt и b.txt (5ed8fdc8...), деревьев about (3e8788ca...), notes (168d5a25...) и sandbox (d564d0bc...) остались прежними. Значит, каждый коммит хранит полный снимок, но неизменившиеся объекты не копируются: новый снимок ссылается на них по хешу. Меняется только изменённый файл и деревья на пути от него до корня, потому что хеш дерева зависит от хешей содержимого.
